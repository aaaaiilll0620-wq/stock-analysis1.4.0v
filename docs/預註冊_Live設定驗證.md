# 預註冊 · dual100 用「live 設定」重新驗證(而非研究設定)

**建立**:2026-08-10,凍結。**在任何 live 設定面板建置完成、看到任何數字之前寫死。**

**動機**:`docs/現況總表_2026-08-09.md` §9-2 記錄的診斷量測(`scripts/live_vs_research_overlap.py`,
純診斷、非預註冊)發現:live 設定(估值窗 2019、籌碼源 institutional_participation)與研究設定
(估值窗 2004、籌碼源 institutional_flow 淨額,= `docs/預註冊_雙確認ADV100萬.md` 驗證用的真身
面板)算出來的雙確認交集,4 個歷史日期 Jaccard 重疊率中位數只有 **0.640**。這代表被核准進實盤
(`docs/預註冊_雙確認ADV100萬.md` §7.1)的是研究設定的規則,但**實際在跑的是 live 設定算出來的
名單**,兩者選股結果只有六到七成一致。

**本文件要回答的問題**:live 設定(= 實際在跑的那個)本身,單獨拿去跑 H1-H5,通不通得過?
這是目前完全沒測過的東西——之前只測過「研究設定通過」跟「兩者名單重疊率」,從沒直接測過
「live 設定自己的績效」。

**不是**要重新設計一個規則:選股規則(composite Top20% ∩ c2 Top20% @ADV≥100萬)不變,
只換底層算 composite 用的設定(估值窗、籌碼源),c2 兩邊定義相同(已於診斷量測確認
c2 不受這兩個覆寫影響,見 `scripts/live_vs_research_overlap.py` 內的說明)。

## 1. 搜尋空間宣告與範圍縮減理由

與 `docs/預註冊_雙確認ADV100萬.md` 相比,本文件**只跑固定 100萬 層**,不建 2000萬/500萬 層
的 live 版本,理由:dual100 的 H2 已證明 17/17 個重選窗全挑 100萬 層,「選哪個 ADV 層」這個
自由度在研究設定上沒有分歧空間,沒有理由假設換成 live 設定會不同。不重跑三組虛無對照
(H3):選股規則本身(composite∩c2、Top20%)已經在研究設定上通過完整虛無檢定;本次只換
底層資料設定,不是在搜尋新規則,額外的選擇性偏誤校正邊際價值低。

## 2. 假設(在看到任何 live 設定數字之前寫死,門檻逐字沿用 dual100 預註冊)

### H1 — 前置閘(in-sample)
live 設定雙確認全期夏普 **>0.68**(0050),且基準階梯①選股階 **>0**。
> 失敗 → 結案,不跑 H2/H4/H5。

### H2 — 主假設(OOS,= dual100 的 H2b,固定 100萬 層,同一段時窗)
在與 dual100 H2 完全相同的 OOS 窗口(訓練窗 ≥60 月起算,即 2010-01~2026-03,195 月)
量 live 設定版本的 OOS 夏普 **且** CAGR 皆勝同段 0050。

### H3 — 滑價敏感度(= dual100 的 H4)
來回滑價拉到 **0.60%** 時,live 設定版本夏普仍 **>0.68**。

### H4 — 六時代穩健(= dual100 的 H5)
六時代中,**至少 4 段** CAGR 勝該層等權母體,**且至少 3 段**夏普勝 0050。

---

## 3. 判定門檻與失敗處置(先寫死)

| 假設 | 通過條件 | 失敗處置 |
|---|---|---|
| H1 | 全期夏普 >0.68 且 ①選股階 >0 | **結案**,不跑 H2/H3/H4 |
| H2 | OOS 夏普 **且** CAGR 皆勝同段 0050 | 否定 |
| H3 | 滑價 0.60% 時夏普 >0.68 | 否定 |
| H4 | ≥4 段勝等權母體 **且** ≥3 段夏普勝 0050 | 否定 |

### 事前宣告的三個出口

1. **H1/H2/H3/H4 全過** → live 設定本身**也**是驗證通過的策略本體,「估值窗/籌碼源
   只揭露不修」的裁決有實證支撐(live 版本自己就過得了關,不需要跟研究版本一致才安全)。
2. **H1 通過但 H2/H3/H4 任一否定** → live 設定**沒有**獨立通過驗證,即使選股規則本身
   (composite∩c2)是對的,目前實際在跑的具體設定組合不安全。**這種情況下不得繼續讓
   live 設定裸跑**,須升級處理優先度(啟動 DataExport0806 遷移對齊研究設定,或改用其他
   方式讓 live 端算出跟研究設定更接近的分數),不得因為「規則本身驗證過」就假設具體
   設定也沒問題。
3. **H1 本身否定** → 比出口 2 更嚴重,live 設定連 in-sample 前置閘都過不了,結案並立即
   標記現行 live 部署為「未驗證運行」,優先度最高。

## 4. 已知會使結論失效的事

1. **面板建置成本**:與 `realbody_scores_adv100w.parquet` 同量級(~2,139 檔、~264,000
   stock-months),預估 1.5~2 小時(6 worker 平行,沿用 `build_realbody_scores.py` 的機制)。
   長跑 build,中途不得打斷(研究紀律 §4)。
2. **c2 兩邊相同的假設**:已於診斷量測階段確認 c2 不依賴 `core.tej_bundle` 的估值窗覆寫
   (c2 因子來自獨立的 `obs_alpha` factor 面板)。若這個假設之後被推翻,本文件的
   「只換 composite 腿」設計需要重新檢視。
3. **母體與研究設定同一批 stock-months**:用同一份 `obs_alpha` 過濾邏輯,確保兩邊比較
   的是同一個母體,不是先有落差就先怪母體不同。

## 6. 結果

> **H1/H2/H3/H4 全過 → 觸發 §3 出口 1。live 設定本身也是驗證通過的策略本體。**
> 2026-08-10 執行,`scripts/build_liveconfig_scores.py`(面板建置 2,624 秒≈44 分,
> 覆蓋率 100.0000%、0 score_error)+ `beat_0050/strategies/dual100_liveconfig_lab.py`,
> 與研究設定同一份 obs_alpha 母體(2,139 檔、263,928 stock-months)、同一段時鐘
> (255 月,2005-01~2026-03)。

| 假設 | 門檻(§3) | 觀測 | 判定 |
|---|---|---|---|
| H1 | 全期夏普 >0.68 且 ①選股階 >0 | 夏普 **0.91**、①選股階 +10.94pp/年 | ✅ 通過 |
| H2 | OOS 夏普且 CAGR 皆勝同段 0050 | OOS 夏普 **1.22** vs 0.86;CAGR **23.83%** vs 16.52%(195月) | ✅ 通過 |
| H3 | 滑價 0.60% 時夏普 >0.68 | 0.60% → 夏普 **0.76**;損益兩平 ≈**0.79%** | ✅ 通過 |
| H4 | ≥4 段勝等權母體 且 ≥3 段夏普勝 0050 | 勝母體 **6/6**、夏普勝 0050 **4/6** | ✅ 通過 |

### 與研究設定(dual100)對照

| | 研究設定(已驗證) | live 設定(本次) |
|---|---|---|
| H1 全期夏普 | 0.89 | **0.91** |
| H2 OOS 夏普 / CAGR | 1.20 / 22.79% | **1.22 / 23.83%** |
| 滑價 0.60% 夏普 / 損益兩平 | 0.73 / 0.71% | **0.76 / 0.79%** |
| 六時代:勝母體 / 夏普勝0050 | 6/6 / 4/6 | 6/6 / 4/6(完全相同) |
| 全期(255月)MDD | −68.7% | −66.9% |

**live 設定在每一項聚合指標上都跟研究設定相當,甚至略優**——儘管
`scripts/live_vs_research_overlap.py` 量到兩者逐月的實際持股名單只有約 6 成重疊
(Jaccard 中位 0.640)。**這兩個發現不矛盾**:個股層級的選中/選出因估值窗/籌碼源
不同而有實質差異,但兩種設定選出來的「投組整體體質」(相對品質、相對便宜)在聚合
統計量上收斂到相近的結果——換句話說,規則本身(composite∩c2 相對排序邏輯)夠穩健,
足以吸收底層資料設定的差異,不是靠精確對到哪一支特定股票才有效。

### §3 出口 1 處置(已觸發)

live 設定(= 目前生產環境實際在跑的那個)**獨立通過驗證**。原本「估值窗/籌碼源只揭露
不修」的裁決,現在有實證支撐——不是因為改了風險大所以賭一把,是因為 live 設定自己
量過,四項門檻都過,聚合表現跟被核准的研究設定相當。**維持現狀,不需要因為這次結果
去啟動 DataExport0806 遷移**(那仍然可以是獨立於本案的其他理由,但不再是「live 設定
可能不安全」這個急迫性)。

**誠實保留(承接自 dual100 原始預註冊,同樣適用於本案)**:零股撮合溢折價無法回測、
MDD 深(全期 −66.9%~−68.7% 級)、動態選池未獨立驗證——這些既有保留事項不因本次
通過而解除,本文件只新增「live 設定本身有驗證」這一項,不覆蓋原始預註冊的其他保留。
