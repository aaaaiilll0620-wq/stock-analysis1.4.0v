### B1 · Phase A→B 契約綁了相位相依的 hash

`run_l3_prospective.py` 的 `decision_contract_payload` 綁 `market_state_sha256`，該值依構造在兩相
必不同（intent 的 `execution_date=None`、所有 `execution_open=None`）。實測 `market_state`
intent `5b670034…` vs exec `9e5a5d48…`；`decision_cutoff_state` 兩側同為 `5b670034…`。
⇒ `--mode execute` 永遠 abort，Phase B 結構上不可達。

**已改綁 `decision_cutoff_state_sha256`**（`l3_assemble.py:728` 定義、`:865` 計算、
`run_l3_prospective.py:840-841` 已 receipt，原本只是沒接上）。`market_state_sha256`
**保留為 recorded-but-not-compared** —— 它是已發佈 intent 連回自身 run receipt 的唯一線索。
`DECISION_CONTRACT_COMPARED_FIELDS`（17）與 `DECISION_CONTRACT_RECORDED_FIELDS` 為具名集合，
`_assert_contract_field_sets()` 在重疊、出現未宣告欄位、或宣告欄位消失時 abort（**雙向**）。

欄位稽核另外查出 `commit_sha` / `harness_sha256` 亦非相位不變，但它 **fail-closed 且有補救**
（從 intent 的 commit 執行），與 `market_state_sha256` 的「永遠失敗」不同，故保留在比較集合
並具名揭露，未擅自放寬。

### B2 · `as_of` 可以無聲落後

`core/b0_route.py` 的 `resolve_as_of_observed_prefix` 用 `min(decision_date, observed_end)` 裁剪，
且 `l3_snapshot.plan()` 原本「必須存在晚於 decision_date 的 session」那條要求被刪、無替補。
實測落差 **17 個日曆日**、不報錯：母體與 ADV20 窗口整體位移，而發佈物上寫著原本的 `decision_date`。

**已修**：宣告日曆必須涵蓋到 `decision_date`，否則 abort 並具名三個事實（覆蓋終點、
請求的 decision_date、原本會解析出的 as_of）。**剛好結束在 decision_date 的日曆仍被接受**
—— 執行 session 可以還不存在，那正是 intent 階段的意義。

⚠ **同一裁剪行為在 adapter 層被第二次認證**：
`tests/test_b0_adapter_parity.py::test_intent_as_of_uses_only_the_observed_calendar_prefix`
（日曆止於 2020-06-29、`DECISION = 2020-06-30`）。已改寫為一正一負。全樹搜尋確認**沒有第三份**。

### B3 · leaf 把機器絕對路徑烙進 hash 綁定欄位

**已還原為 repo-relative**，且修好的 builder **逐位元重現 base `216d62db` 的 payload hash**

caller 給的 repo 外絕對路徑改為 abort；`declared_landing_dir` / `declared_pre_2019_dir`
