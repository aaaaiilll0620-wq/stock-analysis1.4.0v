## 1. 問題

`stock_dividend_pit.csv` 有 **1,011 / 9,120** 筆 `NOT_RECONSTRUCTIBLE`。
落在 141 期窗口（2014-07-31 … 2026-03-31）內的有 **377** 筆。
持有中遇到任一筆，run 依 §6.1.12 中止——`L2-af1b4d90c29b3b5f` 就是這樣停在第 2 期的。

兩個原因，成因與處置**完全不同**，故分開凍結：

| 原因 | 全庫 | 141 期窗口 |
|---|---|---|
| capitalisation recorded without an ex-right flag: no distribution ratio | 851 | **312** |
| the receivable has no observable credit date | 160 | **65** |

## 2. 規則 CA-1 · 無除權旗標的資本額變動 ⇒ **不是持股人事件**

**判定**：`reason` 含 `ex-right flag` 的事件，`holder_multiplier = 1.0`，
既有持股數不變，不產生 SecurityReceivable。

**這不是近似，是正確讀法。三條獨立證據：**

1. ⟨M⟩ **官方零筆**。312 筆全部比對 TWSE/TPEx 除權公告採集結果
   （`artifacts/stock_dividend_multiplier_audit/coverage.csv`，
   `transport failures: 0`，已收斂），
   **有正配股比例者 = 0**。若真按持股比例配給既有股東，官方公告會有。
2. ⟨M⟩ **312 筆全部帶配發數量**。新股確實發行，但沒有除權旗標
   ⇒ 那些股票流向認購人（現增）、債權人（CB 轉換）或員工（認股／員工紅利），
   **不是按持股比例配給既有股東**。
3. **程式本來就同意**。`core/b0_bonus_share_source.py` 的
   `FORBIDDEN_MULTIPLIER_SOURCES` 已明列 `paid_capital_increase_shares`
   與 `employee_bonus_shares` 為**禁止**用來導出 multiplier 的來源。
   把這些事件當成持股人配股，正是 C-51 禁止的事。

**否證條件**：若日後發現任一筆「無除權旗標」事件在官方公告中帶正配股比例，
本規則對該筆失效，且整條規則須重新檢視——不是打補丁。

## 3. 規則 CA-2 · 無可觀察入帳日 ⇒ 流動性凍結窗口 **59 個日曆天**

**判定**：`actual_credit_tradable_date` 缺失時，

```
credit_tradable_date := next_trading_session( ex_right_date + 59 calendar days )
```

`next_trading_session` 取宣告日曆中第一個 **≥** 該日期的 session。

**59 的來源，以及它為什麼可以在預註冊裡出現**

⟨M⟩ 取自**可重建事件的實際入帳落差分布**（n = 8,109）：

```
lag = actual_credit_tradable_date − ex_right_date（日曆天，nearest 分位）
  p50 = 44    p75 = 51    p90 = 59    p95 = 65
```

**59 = p90。**

⚠ 這個數字是**資料屬性**，不是結果屬性：它由「已知入帳日的事件」量得，
與任何投組、NAV、報酬、績效指標無關。因此它不觸犯 §9.6a-R2 條件 2
（`no strategy-dependent portfolio, NAV, return, performance metric … produced or viewed`）。
若它取自任何策略結果，本文件就不成立。

**為什麼取 p90 而不是 p50、更不是 T+2**

- ⟨M⟩ **實測落差 ≤ 2 天者佔 0.0%**。T+2 是**買賣交割**慣例；
  配股入帳是**公司行為匯撥**，中位數 44 天。
  以 T+2 填值等於讓投組提早約六週取得可賣股票——**可以賣掉還沒到手的股票**，
  是對投組有利的前視偏誤。
- 填補缺值的方向必須讓策略**吃虧**而非佔便宜，否則回測系統性偏高。
  晚入帳的代價是「該賣時賣不掉」，方向正確。
- p50 無偏但仍有一半情況偏早；p90 保守。**取保守。**

**否證條件**：若日後取得這 65 筆中任一筆的真實入帳日，該筆一律以真實值為準，
凍結窗口只在**沒有觀測值**時生效。真實值與 59 天的落差須逐筆記錄，不得靜默取代。
