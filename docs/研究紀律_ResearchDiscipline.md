# 研究紀律 — 什麼事做了會讓結論失效

`CLAUDE.md` 講程式碼結構與輸出風格,`AGENTS.md` 講雙 AI 角色分工,
**本檔講「哪些動作會靜默毀掉結論」**。開工前先讀本檔。

這是一個**量化研究**專案,核心資產不是程式碼,是**沒有被污染的結論**。
一次靜默的錯誤對照可以讓幾個月的結論全部作廢,而且**不會有任何報錯**。
專案史上已發生四次(L1 報酬線、L2 含息、L3 真身/替身、L4 基準用錯),**全部都是靜默的**。

---

## 1. 三條會靜默毀掉結論的線

| # | 規則 | 唯一入口 | 違反的後果 |
|---|---|---|---|
| 1 | **報酬線只能是 `exec_ret.fwd_x`** | `lab_paths.load_panel()` | `obs_alpha.fwd` 有兩個反向偏誤,淨誤差**正負隨換手率變動**,無法事後修正 |
| 2 | **綜合分只能用真身 `real_composite`** | `lab_paths.load_real_panel()` | 替身 vs 真身 Top-20% 名單 Jaccard 僅 **0.35**、IC 方向相反 |
| 3 | **判定報基準階梯三階,不是單一 0050** | `honest_backtest.Engine.report_ladder()` | 等權策略開場就欠 0050 **5.77pp/年**;拿它當及格線會把「加權方式」誤判成「沒有 alpha」 |

這三個入口**刻意設計成會 KeyError / raise**:
`load_panel` 不回傳 `fwd` 欄、`load_real_panel` 不回傳 `composite` 欄、
`resolve_realbody` 對「面板門檻 > 需求門檻」直接 raise。

> **這些 raise 是功能,不是 bug。** 正確反應是**去補資料**,
> 不是 try/except、不是放寬門檻、不是繞過去。
> 繞過去的代價不是程式壞掉 —— 是**數字看起來很正常但意義已經變了**。

細節:`現況盤點_2026-07-29.md`、`基準階梯_BenchmarkLadder.md`。

## 2. 預註冊紀律(**單發射擊制**)

**看到樣本外數字之前**,假設 / 量測協定 / 判定門檻 / 搜尋空間必須先寫死在 `docs/預註冊_*.md`。

- 診斷(in-sample)可自由跑,但**診斷不是結論**,不得據以下生產決策。
- 預註冊凍結後:**不得改門檻、不得換母體、不得換報酬線、不得事後追加 arm**。
- **否定結果照登**,與正面結果同等份量。本專案已正式結案兩條路
  (864-arm 單因子掃描、high52_prox)—— 那是資產,不是失敗。
- 搜尋空間**如實申報**,含「這個規則本身是先前工作挑出來的」這類無法完全校正的部分。

**為什麼這麼嚴**:`high52_prox / N=8 / ADV≥100萬` 的 in-sample 是
CAGR 22.50% / 夏普 0.77 / 虛無 p=0.000 —— 漂亮到不像話,**照樣被否定**
(walk-forward OOS 夏普掉到 0.52、DSR p=0.342)。
**in-sample 有訊號 + walk-forward 垮掉 = 過擬合。**
