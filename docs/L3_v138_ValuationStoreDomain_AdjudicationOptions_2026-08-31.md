**⚠ 先更正 A-3 的一項事實描述。** 九項選項書 A-3 的〈事實〉寫：

2026-06  ['2026-06-29', '2026-06-30']      2026-02  ['2026-02-26']

`2026-06-29` 不是月底；`2025-09-26` 也不是、且不是 `2025-09-30` 的前一個 session。
止於 2026-07-31 是對的；`twse_2026-08-28.json` / `tpex_2026-08-28.json` 未 harvest 也是對的。

**⚠ 更正（同日，本文件初版）。** 初版在此寫「它沒有可陳述的規則」。**那句是錯的**，
在追查 harvester 時發現並在此更正 —— store 不是沒有規則，是**同時materialise了兩條規則**：

```
harvest_official_pbr.decision_sessions()    月末當天或之前最後一個 session（涵蓋稽核用）  123
harvest_official_pbr.route_as_of_sessions() 月末之前最嚴格的前一個 session（§6.6，路線用）  87

實際 store                                                                          180

```

`route_as_of_sessions` 的 docstring 自陳兩者「同一日期當月末不是 session、差一個 session 當它是
—— 141 個決策月裡有 85 個」。**store 完整包含兩個規則集**，另加 7 個凍結窗之後、
沿同樣兩兩成對模式手工補的 session。所以本項的問題不是「定義域不存在」，
而是**定義域被定義了兩次，因為有兩個不同的問題在問它**。

**L3 實際讀哪一天：** §6 的 stop rule 把 `as_of` 綁在**決策日之前最後一個完成的 session**
（`research/b0_l3/l3_snapshot.py:176-178`，且 `run_l3_prospective.py:1163` 註明
「§6.6 can move as_of back across a month boundary」）。
⇒ 決策日若是月底，**L3 要的是月底的前一個 session，不是月底本身**。
Month 1（decision 2026-09-30）要的是 **2026-09-29**。

**成本：** harvester 直接向 TWSE/TPEx 取，任一 session 皆可回抓、不會過期（C-48/C-49 禁止 TEJ 替代）。

## 2 · 選項

**甲 · 裁定定義域為「每個決策期的 `as_of` session」。**
即決策日前最後一個完成的 session —— L3 真正讀的那一個。
- 後果：定義域與讀取點有因果關係，不是慣例。每期只需一個 session。
- 注意：這在九項選項書裡被寫成 A-3-乙，並以「改變 store 的定義域，屬於來源語義變更」為由未採。
  **§1 的量測改變了那個理由**：沒有既存定義域可被「改變」，本項是第一次定義它。

**乙 · 裁定定義域為「每月月底 session」，並要求 L3 的 `as_of` 對齊月底。**
- 後果：store 的形狀與名目一致。
- 代價：**要改的是 §6 的 stop rule，不是 store。** 那動的是決策時點語義
  （`as_of` 從「決策日前最後一個 session」變成「決策日當天」），影響每一個 PIT 邊界。
  **成本與風險遠高於本項的標的，應標示為「這不是資料裁決，是決策語義裁決」。**

**丙 · 不定義域，改立即時規則：每次執行前檢查該期 `as_of` 是否在 store 內，不在就 harvest。**
- 後果：不必回填歷史，Month 1 也能過。
- 代價：「store 裡有什麼」永遠不是可預測的事實，只能靠執行時查詢；
  且它把一個資料完整性問題轉成每期的操作步驟，而操作步驟會被漏做。

**丁 · 維持不裁決。**
- **應標示為實質選項而非拖延**：下一個 decision session 會再撞一次同一件事，
  且每撞一次都要臨時判斷該不該補、補哪一天。

## 3 · 建議

**甲。** 理由經 §1 的更正後改變，但結論不變：兩條規則裡只有 `route_as_of_sessions`
對應 L3 實際讀取的 session（§6.6），另一條服務的是涵蓋稽核，是另一個問題。
所以本項要裁的是**哪一條是規範**，而不是「發明一個定義域」，也不是「變更來源語義」——
九項選項書 A-3 拒絕此選項時用的正是後面那個理由，該理由在量測後不成立。
採甲之後必須一併說明：稽核那條規則產出的 123 個 session 是什麼地位
（`route_as_of_sessions` 的 docstring 已警告「把已封存面板建在稽核集上，
會把凍結輸入綁到一個路線從不讀取的 session」）。
乙 應明文記為「它要改的是 §6 而不是 store」，以免日後被當成同級選項。
丁 應明文記為會週期性復發。
